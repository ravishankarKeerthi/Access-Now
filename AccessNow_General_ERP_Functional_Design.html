Place master

One canonical record for each physical location. Place identity is separate from its owner or operator.

Register a place

Master-data controls

Duplicate prevention: external map reference + address + geo proximity.

Ownership: one place can have multiple buildings, facilities or operators.

Data lineage: source, entered by, created date, last confirmed date.

Versioning: never overwrite previous assessment records.

Do not force a physical place into a Customer or Supplier master. Link an owner/operator only when applicable.

Accessibility assessment

An assessment is a transaction against a place and a defined accessibility profile. Each criterion is stored as an individual result.

Mobility checklist

Data rule: production checklist lines store criterion, response, observation, evidence and severity. Response values are Available, Unavailable, Not Applicable and Not Verified. A checkbox alone is insufficient.

Public report intake

Visitors, staff and facility operators can report a changed condition. Reports do not directly overwrite approved assessments.

Validation rules

RuleBusiness conditionERP behaviour
VAL-01Place, profile, assessor and date mandatory.Block submission when missing.
VAL-02Every applicable criterion needs a response.Block and list incomplete rows.
VAL-03Not Verified is not Available.Never count unknown as passing.
VAL-04Evidence-required criterion needs evidence or approved exception.Block or route exception for approval.
VAL-05Critical criterion is Unavailable.Prevent positive profile result; create corrective action per policy.
VAL-06High-risk verifier cannot approve own assessment.Enforce segregation of duties.
VAL-07Assessment reaches validity date.Mark profile stale and queue reassessment.
VAL-08Critical report is confirmed.Override affected published criterion and flag reassessment.
VAL-09Similar place / facility / issue / time exists.Flag possible duplicate; do not auto-delete.
VAL-10Critical report is closed.Require completion evidence and independent verification.
VAL-11Published status changes.Append old/new value, user, time, source and reason.

Profile status calculation

INPUT: Place + Accessibility Profile + effective criteria version 1. Find latest approved assessment for this place and profile. 2. Check assessment validity. 3. Apply active, verified issue overrides to affected criteria. 4. Evaluate applicable criteria: Available = passes for this assessment Unavailable = does not pass Not Applicable = accepted only with reason / rule Not Verified = unknown; never treated as pass 5. Apply critical-criterion rules. 6. Derive status and store calculation time + source references. OUTPUT: - Verified for selected profile - Partially accessible - Not accessible for selected profile - Confirmed access issue - Insufficient information - Not assessed / expired Never calculate one universal accessibility score across profiles. A place may pass mobility checks but have unverified visual or hearing access. Public display must show profile, assessment date, validity and limitations.

New AccessNow capability

Masters: Place, Facility, Accessibility Profile, Criterion.

Transactions: Assessment, Report, Verification, Corrective Action.

Supporting: Evidence, Condition History.

Interfaces: Public portal, facility portal, mapping provider, notification service.

Do not duplicate the ERP's employee, organisation, task, document or notification masters unless there is a genuine functional gap.

Mapping and portal integration

  1. Use a mapping service for map display, geocoding and place discovery.
  2. Store external place reference and coordinates in Place Master, subject to provider terms.
  3. Retrieve AccessNow status from ERP records/API; never infer accessibility from map-provider data.
  4. Display profile, status, last verified date, expiry and limitations.
  5. Only show accessible-route guidance when validated route-accessibility data exists. Ordinary route directions do not prove a route is accessible.
  6. Secure API keys, restrict allowed APIs/domains and follow provider attribution and data-use terms.
